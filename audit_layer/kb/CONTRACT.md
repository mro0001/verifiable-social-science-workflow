# kb Contract

Purpose. The audit layer's knowledge base (appendix A2.4), the pipeline-standards knowledge corpus of goal 4 of MANUSCRIPT_WORKFLOW.md, moved here from ospipe on 2026-10-29. Entries the repository's knowledge base server, `workflow-kb`, serves to any future session.

## Produces

- `audit_layer/kb/corpus/` holds the entries and a regenerable `llms.txt` index. Each entry is one `<group-lowercase>/<id>.md` file. Its frontmatter holds exactly six keys (`id, title, source, source_commit, updated, group`). Its body holds an H1 title, a point paragraph, the facts, and then an optional `## Gaps` section and an optional `## Consult also` section.
- The groups in use are `CAPABILITIES` (tools and skills a session can propose), `FORMATS` (record shapes), `GUIDELINES` (standing rules for a session, among them the authoring guide for new procedures), `LOOP` (build and return procedures), `PROCEDURES` (the procedural graphs), and `VERIFICATION` (witness rules).
- The group `PROCEDURES` (`audit_layer/kb/corpus/procedures/`) is generated by `graph-entries`, one entry per procedural graph, and is never edited by hand. Its entries are written from a plain copy of `verification_procedures/graphs/` and `contracts/`, with `registry.yaml` when there is one, and are regenerated whenever a graph changes. Every other group is written by hand.

## Commands

Run from the repository root. `--corpus DIR` names another corpus, and the default is `audit_layer/kb/corpus/`.

- `python3 -m audit_layer.kb check [--corpus DIR]` checks every entry and the index `llms.txt` against the entry rules in `check.py`. It prints `OK: <n> entries` and exits 0, or prints `FAIL (<n>)` and one problem per line and exits 1. Its last rule asks that `llms.txt` be exactly the index the corpus gives, and it is read once every other rule passes.
- `python3 -m audit_layer.kb llms [--corpus DIR]` rewrites `llms.txt` from the corpus alone, keeping its first `# ` and `> ` lines, and prints `rewrote` or `unchanged`.
- `python3 -m audit_layer.kb export --out FILE [--corpus DIR]` writes every entry to one JSON file (`kb-index` version 1), the exported index the knowledge base server's graph answers from.
- `python3 -m audit_layer.kb graph-entries --procedures DIR [--corpus DIR] [--date YYYY-MM-DD] [--check]` writes one entry per graph in `DIR/graphs/*.yaml` from the graph and the contract it names, removes the entry of a graph that is gone, and rewrites `llms.txt`. A graph that `DIR/registry.yaml` names takes the registry's procedure as its title and its events and phrases as its triggers. An unchanged entry keeps its bytes, and a changed one carries `--date`, today by default. It prints one line per added, changed, or removed entry. With `--check` it writes nothing and exits 1 when any entry would change.
- `python3 -m audit_layer.kb source-check --root DIR [--corpus DIR]` compares each entry's recorded `source_commit` with the file at `DIR/<source>` and prints one line per entry (`same`, `changed`, `not_found`, or `not_checked`, then the id and the source) and a count per status. A git short hash or a web address is `not_checked`, and a source that is absolute, holds `..`, or is not a file under `DIR` is `not_found`, so nothing outside `DIR` is read. It exits 1 when any source changed.

## Frozen

- The entry shape under Produces is the conformance target. This module invents no fields.
- No `/Users/` or local filesystem paths in entry bodies. No relative links.
- `source_commit` holds `sha256:` and the first 12 hex characters of the sha256 of the source file.
- Serving is outside this module. This module never runs a server. The knowledge base server `workflow-kb` (`python3 -m connections serve kb --index FILE`) serves the corpus read only, from the file `export` writes.

## Soft

- Which standards get entries and when; entry wording; group additions.

## Consumers

- Any AI session in any project, through the knowledge base server `workflow-kb`, which runs the graph `mcp_kb` (`verification_procedures/graphs/mcp_kb.yaml`) once per call. No other module imports this one.
- `workflow-kb` took the place of the earlier outside server, `pipeline-kb`, on 2026-10-29.
- The `mcp_kb` graph answers from a file written by `python3 -m audit_layer.kb export` and given with each call, and never reads the corpus itself.

## Fixture

- The conformance test (`audit_layer/kb/tests/test_kb_corpus.py`, moved from `ospipe/tests/`) validates the real corpus against the frozen shape; the shape rules themselves are the fixture. It also checks the generated PROCEDURES group, the authoring guide's entry, and three checks across layers, made through files and command lines only (`graph-entries --check` on a fresh copy of the graphs and contracts, `source-check --root .`, and a search of an export through the `mcp_kb` graph). Entries contain no real project data, so the synthetic-fixture rule is satisfied by construction.
